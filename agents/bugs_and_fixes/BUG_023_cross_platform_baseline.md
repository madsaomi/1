# BUG-023 — Windows fingerprint не совпадает с чистым Linux checkout

Дата: 2026-10-27. Автор: Codex. Статус: ИСПРАВЛЕНО, PLAN-032.

## Симптом
Pre-push проверка выявила166CRLF в content.js. Исходный PLAN-030 baseline хранит raw SHA256 этого Windows-файла. .gitattributes задает text=auto/eol=lf, поэтому Git записывает LF, а чистый Linux checkout получил бы другой SHA256 и упал бы в protected-test, хотя данные не менялись.

## Причина
Тест сравнивал raw filesystem bytes между разными представлениями переносов. Локальный49/49 запуск не моделировал Git normalization.

## Решение
Исходный baseline не меняется. Protected-test принимает только raw/LF/CRLF эквиваленты того же текста; для .dockerignore сначала удаляет ровно2заявленныхallowlist-добавления, затем сравнивает fingerprints. Любое изменение символов данных/config по-прежнему нарушает hash. Git attributes, production-файлы и контент не менялись в этом исправлении. Дополнительно выполнить проверки на экспорте Git index с LF, а не ограничиться текущей рабочей папкой.

## Предотвращение
Проверять переносимость fingerprint-тестов до push. Не обновлять snapshot под текущую ОС и не убирать защиту данных. Только EOL-эквивалентность допустима автоматически.
