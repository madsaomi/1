# BUG-021 — Прозрачная шапка, видимый live-статус и уровни карточек

Дата: 2026-10-27. Автор: Codex. Статус: ИСПРАВЛЕНО В КОДЕ; BROWSER-ПРИЕМКА ОТКРЫТА, PLAN-031.

## 1. Симптом
Владелец сообщил: под sticky-шапкой видны заголовки; под курсами выведено «Все программы. Программ: 7.»; списки соседних карточек начинаются на разных уровнях. Чтение текущего кода подтверждает эти причины. Карта в отдельных скриншотах пустая; причина локального рендера пока не доказана.

## 2. Первопричина
Шапка использовала полупрозрачный токен chrome. У role=status не было sr-only, хотя JS обновляет его для объявления результата фильтра. Вторая карточка содержит дополнительную строку subtitle, а flex:1 у описания распределял остаточную высоту перед списком. При удалении global scroll-padding независимая проверка обнаружила еще один риск: mobile-выбор филиала прокручивает #map-status к началу окна, значит ему также нужен offset sticky-шапки.

## 3. Решение
Непрозрачная paper-поверхность шапки и ее продолжение на поля; общий anchor-offset (81px шапка+16px) у секций, карточек, экзаменов, карты и скидок. Status остается live, визуально скрыт. Flex-column карточки сохранены, description больше не flex:1; на двух колонках заголовок и описание имеют одинаковую минимальную высоту без обрезания. Footer прижат margin-top:auto. Добавлены16px skills с декоративными SVG. В процессе source-review исправлена неверная начальная формула full-bleed inset до передачи: заменена paint-only shadow/clip, не расширяющими layout.

## 4. Предотвращение и границы
При изменении scroll-padding проверять все цели scrollIntoView, включая программные переходы. Не скрывать live-region через display:none/hidden. Проверять карточки с subtitle и длинным описанием. Min-height не гарантирует точного выравнивания при любом увеличении шрифта — нужна реальная browser-приемка. Публичная диагностика Google/Yandex не заменяет проверку iframe/переключателя в контексте сайта и его CSP; не править JS по гипотезе file://.
