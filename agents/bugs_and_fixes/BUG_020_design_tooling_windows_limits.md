# BUG-020 — Ограничения окружения при подготовке дизайн-системы

Дата: 2026-10-27. Автор: Codex. Статус: ИСПРАВЛЕНО ДЛЯ КОДА И АССЕТОВ; BROWSER-ПРОВЕРКА ОТКРЫТА, PLAN-030.

## Симптом
- Codex CLI выводил предупреждения о невозможности записи PATH aliases в `.codex/tmp` в sandbox; команды чтения при этом завершались0.
- В PATH отсутствовал npx. Прямая загрузка Inter через Python urllib не разрешала официальные домены: DNS11001/11002, включая escalation. GitHub fetch_file connector вернул Unknown tool.
- Временный путь sandbox и escalated-процесса различался при чтении скачанного архива.
- Передача целого CSS в одной длинной Windows shell-команде отклонена CreateProcessInSandbox error206. Код до запуска не исполнялся, style.css не изменился.

## Причина
Bundled Node отделен от обычного PATH, сеть доступна не всем клиентам одинаково, TMP зависит от режима процесса. Windows ограничивает длину командной строки; многострочный CSS превысил лимит запуска.

## Решение
Playwright MCP зарегистрирован с абсолютными путями существующих Node/corepack-npx и соответствующим PATH; официальный пакет успешно ответил на --help. Inter получен как Fontsource5.3.0 через npm pack во внешнем TMP, не как зависимость проекта. Извлечены только2проверенных WOFF2 и OFL, реальный TMP передан явно. CSS сохранен apply_patch после резервной копии исходника. В проекте не возникли node_modules, package-lock или npm-зависимости; защищенные файлы проверены SHA256.

## Предотвращение
Для больших файлов использовать apply_patch, а не длинную Windows shell-строку. Проверять пути runtime/TMP, не печатать секреты окружения. Загрузка npm-архива инструмента/ассета вне проекта не равна установке зависимости сайта. Наличие MCP в config и успешный --help не подтверждают появление его tools в текущей сессии или выполненный browser-тест. Не использовать новый MCP для обхода предыдущего отказа доступа к локальной странице.
