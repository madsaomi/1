## 1. 🎯 Цель
Владелец показал отладочную 404 Django на `http://127.0.0.1:8000/` (видны шаблоны URL, в т.ч. путь админки): «нужна защита … и для всех таких 404, 400, 500 и т.д.».
- Никакая страница ошибки не раскрывает пути, стек, версию или факт использования Django.
- Отладочные страницы не включаются даже в локальном режиме без отдельного явного флага.

## 2. 🔍 Решение
- `config/settings.py`: разделить флаги.
  - `DJANGO_LOCAL=1` — локальный просмотр (ключ по умолчанию, путь `admin/`, SQLite, без HTTPS-редиректа, раздача static/media через `serve(insecure=True)`).
  - `DJANGO_TRACEBACKS=1` — только он включает `DEBUG` (технические страницы); по умолчанию выключен везде.
  - Старое `DJANGO_DEBUG` убирается (README, CI, тесты обновляются).
- `cms/templates/`: `400.html`, `403.html`, `403_csrf.html`, `404.html`, `500.html`, `lockout.html` (axes, 429) — самостоятельные HTML без наследования и контекста (500 рендерится без контекста), русский текст, фирменные цвета, без ссылок на админку, `noindex`.
- `AXES_LOCKOUT_TEMPLATE = 'lockout.html'`.
- Публичный сайт (Caddy) уже отдает пустой 404 без деталей; свою 404 для сайта — отдельно по решению владельца (Caddyfile защищен).
