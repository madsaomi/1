## 1. 🎯 Цель и контекст
- **Проблема / Задача:** Владелец предоставил брендбук и логотип «Stanford Language Center» и уточнил фирменные цвета: жёлтый #FFB703 (уже применяется) и чёрный **#070707** (сайт сейчас использует #171717/#111111/#0d0d0d). Также прислана страница брендбука с фавиконом — жёлтая скруглённая плашка с чёрным знаком S (стр. 11, ряд размеров 212/150/110/70 px).
- **Ожидаемый результат:** Все «чёрные» поверхности/тексты сайта используют фирменный #070707 через CSS-переменные; фавикон соответствует брендбуку; автоматические проверки (палитра, контраст AA, protected-файлы) проходят без изменений контента и логики.

## 2. 🔍 Анализ и затронутые компоненты

### Факты из исследования:
- `assets/stanford-icon.svg` **побайтово идентичен** `Logo/Icon.svg` из папки бренда — знак S в шапке уже фирменный, менять не нужно.
- `Logo final.svg` содержит текст через `<text>` со шрифтами MinionPro — в браузере без установленного шрифта развалится. Шапка уже воспроизводит лингва-блок живым текстом («Stanford» + «language center») + знак S, что и есть фирменный лого-блок. Файлы лого не подключаем.
- Тест `validate_html.py`: каждый hex в style.css обязан быть #FFB703 или нейтралью (R=G=B) — #070707 нейтраль, проходит.
- Тест `design-system.test.mjs`: контрастные пары ≥4.5:1 (фокус ≥3:1). Замена чёрного на более тёмный #070707 только увеличивает контраст.
- Protected-базлайн (`plan_030_baseline.json`): content.js, Dockerfile, Caddyfile, railway.json, .dockerignore, package.json — **style.css и index.html не защищены**, правки допустимы. Тексты и script.js не меняем → тесты копии/семантики проходят.
- `.dockerignore` разрешает `assets/` целиком — новый файл фавикона попадает в Docker-контекст автоматически.

### Затронутые файлы:
- `[MODIFY]` `style.css` — только значения токенов в `:root` и `html[data-theme="dark"]`:
  - `--ink: #171717 → #070707`; `--button-ink: #111111 → #070707`; `--focus: #111111 → #070707`; `--dark-panel: #171717 → #070707` (светлая тема);
  - `--paper: #0d0d0d → #070707` (тёмная тема).
  - Нейтральные серые (#151515, #1b1b1b, #f5f5f5 и т.д.) остаются производными нейтралями — палитра это разрешает.
- `[NEW]` `assets/favicon.svg` — фавикон по брендбуку: скруглённый квадрат #FFB703 (rx ≈ 21%), знак S из Icon.svg перекрашен в #070707, масштаб ≈ 1.4, центр совпадает.
- `[MODIFY]` `index.html` — одна строка: `<link rel="icon">` → `assets/favicon.svg`. `assets/stanford-icon.svg` остаётся знаком в шапке.

### Зависимости и влияние:
- Новые библиотеки: НЕТ.
- Логика JS, контент, цены, контакты, конфиги: НЕ затрагиваются.
- Breaking changes: НЕТ. CSP/img-src 'self' покрывает новый локальный SVG.

### Осознанные решения (самостоятельные, в рамках запроса):
1. **Шрифты брендбука (Minion Pro, Proxima Nova) НЕ внедряем**: коммерческие Adobe-шрифты без лицензионных файлов, CSP требует локальные WOFF2, тест закрепляет Inter как локальный шрифт. Вопрос вынесен владельцу отдельно.
2. Полный лого-файл в шапку не ставим (текст в SVG зависит от MinionPro) — шапка уже рендерит блок лого живым текстом.
3. Знак S в шапке остаётся жёлтым (как в лого-блоке); фавикон — по странице брендбука 11 (жёлтая плашка, чёрный S).
