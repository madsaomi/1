## 1. 🎯 Цель и контекст
- **Задача владельца:** «сайт статический, но с админ-панелью — скрытно; люди видят только статику; нужна красивая админка; база — Postgres; Django-админка выглядит старо → переделать дизайн» (Unfold).
- **Результат:** администратор центра входит в скрытую красивую админку (на русском, в цветах Stanford), меняет курсы, цены, контакты, филиалы, фото, преподавателей, результаты, цифры, включает/выключает «Демо-режим» и нажимает «Опубликовать» → через несколько минут статический сайт обновлен.
- **Проверенные факты (2026-11-06):** django-unfold 0.110.1 (1 ноября 2026, MIT, Django 5.2/6.0/6.1, Python ≥3.12); Django 6.1.3 (Python ≥3.12); Railway «Wait for CI» держит деплой до успешных GitHub Actions на push, иначе SKIPPED (настраивается в UI сервиса).

## 2. 🏗️ Архитектура

```
Посетитель ──HTTPS──► site (Caddy, статика: index.html, content.js, assets/)   ← не меняется по природе
                          ▲ Railway autodeploy из main, только при зеленом CI («Wait for CI»)
                          │
GitHub main ◄── 1 коммит: content.js + index.html + assets/uploads/** ── «Опубликовать»
                                                                              │
Администратор ──HTTPS──► cms (Django 6.1 + Unfold, скрытый домен/путь) ───────┘
                          │  Postgres (Railway) — данные; Volume /data/media — загруженные фото
```

- Один генератор: `build.mjs` (Node) — его же вызывает cms при публикации (Node 22 в образе cms).
- `content.js` — опубликованная копия данных в git (история, откат `git revert`, резерв на случай потери базы).

## 3. 🧱 Модель данных (app `content`)
| Модель | Поля | Источник сейчас |

## 5. 🔐 Безопасность и скрытность
- Отдельный сервис на своем домене Railway (или поддомене владельца) + секретный путь `ADMIN_PATH`; `X-Robots-Tag: noindex`, robots disallow.
- Django: DEBUG off, SECRET_KEY/DB/токены — только переменные Railway; Secure/HttpOnly cookie, HSTS, CSRF_TRUSTED_ORIGINS; django-axes (блокировка перебора паролей); опционально 2FA.
- GitHub: fine-grained token **только** на `madsaomi/1`, **только** Contents read/write; владелец сам вносит его в Railway — в чат и git не попадает.
- Публичный сайт не получает доступа к базе и cms вообще.

## 8. 🛡️ Риски и откат
- **Ошибочная публикация:** CI не пропустит невалидное; плохой, но валидный контент — откат `git revert` коммита публикации или повторная публикация.
- **Railway «Wait for CI» пропускает деплой** (отзывы сообщества): статус в админке + инструкция ручного Redeploy.
- **Конфликт правок агента и cms в `content.js`:** после запуска cms содержимое правится только через админку; агент меняет код, не данные.
- **Потеря базы:** бэкапы Railway + `content.js` в git → `import_content`.
- **Откат всего:** сервис `site` не зависит от cms; отключить cms — сайт продолжает работать из последнего `content.js`.

## 9. ✅ Ответы владельца (2026-11-06)
- Домен: технический домен Railway + секретный путь `ADMIN_PATH`.
- Учетные записи: только владелец (одна запись; роль «Администратор» в модели прав оставить на будущее, не создавать пользователей).
- 2FA: да — TOTP (Google Authenticator) на входе; библиотеку (django-otp / django-two-factor-auth) и совместимость с Unfold проверить в начале этапа 2.
- Данные после запуска меняются только через админку; агент меняет только код.
