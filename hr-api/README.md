# HR API — анкета для работы

Маленький сервис для страницы `career.html`: принимает анкету с фото, проверяет её, собирает **один PDF-файл с резюме** и отправляет документ в Telegram HR через Bot API.

Сайт остаётся статическим; сервис — отдельный контейнер.

## Что защищено
- Только `POST /career`, JSON, обязательный заголовок `X-Career-Request: 1`.
- Проверка `Origin` (переменная `ALLOWED_ORIGIN`), CORS только для этого адреса; preflight проверяет также метод и список заголовков.
- Лимит тела запроса 3,5 МБ; фото ≤1,4 МБ, JPEG 200–2000 px, пережимается через `sharp` до 900 px и качества 82 (EXIF и лишние данные удаляются).
- Строгий список полей, запрет лишних полей и honeypot `company`.
- Ограничения текста: ФИО 2–60, Telegram 32, образование/сертификаты 80, «о себе» 20–400; HTML-символы вырезаются, управляющие — заменяются.
- Только известные вакансии/опыт/уровень; телефон строго `+998` и 9 цифр.
- Анти-спам: не больше 4 отправок с одного IP за 30 минут (в памяти, без журналирования данных).
- PDF собирается в памяти: на диск ничего не пишется, после отправки буферы освобождаются.
- Токен бота и chat id HR — только в переменных окружения, браузер их не видит.

## Переменные окружения
| Переменная | Обязательно | Описание |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | токен бота от @BotFather |
| `TELEGRAM_HR_CHAT_ID` | да | chat id HR; несколько — через запятую, например `111111,222222`. Каждый HR должен нажать Start у бота |
| `FEEDBACK_BOT_TOKEN` | для жалоб | токен отдельного бота для жалоб (страница `/feedback`) |
| `FEEDBACK_CHAT_ID` | для жалоб | chat id получателя жалоб; несколько — через запятую. Получатель должен нажать Start |
| `TURNSTILE_SECRET_KEY` | нет | секретный ключ Cloudflare Turnstile (проверка «я не робот»). Задан — каждая анкета и жалоба должна прийти с действительным токеном своей формы, иначе `403 captcha`; Cloudflare недоступен — `503 captcha_unavailable`. Пусто — проверки нет. Ключ сайта (Site Key) вписывается в админке, «Настройки сайта» |
| `ALLOWED_ORIGIN` | да | адрес сайта, например `https://1-production-8f16.up.railway.app` |
| `PORT` | нет | порт, по умолчанию `8787` |
| `HR_DRY_RUN` | нет | `1` — проверить приём и PDF без отправки в Telegram (локально) |
| `HR_TRUST_PROXY_HOPS` | нет | целое число 0–10; по умолчанию `0`, заголовок `X-Forwarded-For` не используется |
| `HR_FORM_LIMIT_PER_HOUR` | нет | сколько отправок одной формы (анкета или жалоба) принимается за час от всех посетителей вместе; по умолчанию `40`, остальные получают «попробуйте позже». Защищает чат от потока с разных адресов |
| `HOST` | нет | адрес привязки; по умолчанию `0.0.0.0`, для локальных проверок — `127.0.0.1` |

Без корректного `ALLOWED_ORIGIN` и обоих реквизитов Telegram сервис отвечает на отправку `503 not_configured`.
В `HR_DRY_RUN=1` реквизиты Telegram не нужны, но `ALLOWED_ORIGIN` обязателен. `/healthz` проверяет доступность
процесса и продолжает отвечать `200`, даже когда приём анкет ещё не настроен. Origin указывается без пути и
завершающего `/`, например `https://example.org`.

Если сервис стоит непосредственно за доверенным Caddy, можно задать `HR_TRUST_PROXY_HOPS=1`: для ограничения
отправок берётся адрес ближайшего клиента из цепочки справа. Порт HR API при этом должен быть доступен только
через закрытую сеть прокси. Не включайте доверие к заголовку на публично доступном API. Если перед Caddy есть
ещё прокси, их доверенные адреса и длину цепочки необходимо настроить отдельно; иначе ограничение может
применяться к общему адресу прокси. Антиспам хранится в памяти одного процесса и сбрасывается при перезапуске.
Если запросы приходят через прокси, а `HR_TRUST_PROXY_HOPS=0`, сервис один раз пишет в журнал предупреждение `[limits]`:
значит, все посетители сейчас делят один лимит (4 отправки за 30 минут на всех).

## Как подключить бота
1. Создать бота у @BotFather, получить токен.
2. Каждый HR открывает бота и нажимает **Start** (бот не может писать первым и не пишет по @username).
3. Узнать chat id: `https://api.telegram.org/bot<TOKEN>/getUpdates` → `message.chat.id`.
4. Задать `TELEGRAM_BOT_TOKEN` и `TELEGRAM_HR_CHAT_ID` в сервисе (несколько HR — chat id через запятую).
   Анкета считается отправленной, если её получил хотя бы один HR; ошибки остальных видны в логах сервиса.

## Деплой
1. Собрать образ: `docker build -t stanford-hr-api hr-api/` (или отдельный сервис Railway с root directory `hr-api`).
2. Подключить сервис к закрытой сети сайта; healthcheck `/healthz`. Публичный домен API не требуется.
3. В переменных окружения сервиса сайта задать `HR_API_UPSTREAM` — внутренний адрес HR API с портом
   (например `hr-api:8787`). В `Caddyfile` уже есть прокси `/career`, лимит тела 4 МБ и CSP `connect-src 'self'`.
   По умолчанию upstream — `127.0.0.1:8787` для локального запуска Caddy и HR API на одном компьютере.
4. В `career.html` адрес API задаётся в `<meta name="career-endpoint" content="/career">` — по умолчанию same-origin. Если сервис на другом домене, указать полный URL и добавить его в CSP `connect-src` и `ALLOWED_ORIGIN` на сервисе.

## Локальный запуск
```sh
cd hr-api
pnpm install
HR_DRY_RUN=1 ALLOWED_ORIGIN=http://127.0.0.1:8080 PORT=8787 node server.mjs
node --test
```
`HR_DRY_RUN=1` проверяет валидацию и сборку PDF, но не отправляет в Telegram.

## Проверки
```sh
node --test
```
Тесты проверяют валидацию, пережатие фото и генерацию PDF, а также HTTP-поток в dry-run без отправки в Telegram,
конфигурацию, CORS, ограничения частоты и доверие к прокси.

## Проверка «я не робот» (Cloudflare Turnstile)
1. Cloudflare → Turnstile → Add widget: домен сайта, режим **Managed**. Получить Site Key и Secret Key.
2. Site Key вписать в админке: «Настройки сайта» → «Ключ сайта Cloudflare Turnstile», опубликовать.
3. Secret Key вписать в Railway в сервис форм: `TURNSTILE_SECRET_KEY`.
Задавайте оба ключа вместе: ключ сайта без секрета ничего не проверяет, секрет без ключа сайта отклонит все формы.
Посетитель обычно ничего не видит; окошко появляется, только если Cloudflare сомневается. Адрес посетителя
сервис в Cloudflare не передаёт. Для локальных проверок есть тестовые ключи Cloudflare (всегда пропускают):
Site Key `1x00000000000000000000AA`, Secret Key `1x0000000000000000000000000000000AA`.

## Жалобы и предложения (`POST /feedback`)
Страница сайта `/feedback` отправляет официальные (имя, телефон, согласие) и анонимные (без имени и контактов)
жалобы. Сервис проверяет поля и отправляет текст отдельному боту `FEEDBACK_BOT_TOKEN` в `FEEDBACK_CHAT_ID`;
ничего не сохраняет. Для анонимной жалобы имя и контакты не принимаются вовсе; адрес отправителя используется только
в памяти для ограничения частоты (4 обращения за 30 минут) и в Telegram не передаётся.
Без `FEEDBACK_BOT_TOKEN`/`FEEDBACK_CHAT_ID` форма жалоб отвечает `503 not_configured`, анкета HR работает как раньше.

Для одного или двух личных чатов с числовыми ID бот показывает три отдельные кнопки
«Новая», «В работе» и «Решено». Галочка отмечает текущий статус, нужный можно выбрать сразу.
Нажатие обновляет кнопки в обеих копиях. Бот получает
нажатия через long polling, поэтому у бота жалоб не должно быть webhook, а `hr-api`
должен работать в одном экземпляре. Связь копий записана в кнопках Telegram.
После замены токена бота или списка получателей старые кнопки теряют силу.
