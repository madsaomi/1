# HR API — анкета для работы

Маленький сервис для страницы `career.html`: принимает анкету с фото, проверяет её, собирает **один PDF-файл с резюме** и отправляет документ в Telegram HR через Bot API.

Сайт остаётся статическим; сервис — отдельный контейнер.

## Что защищено
- Только `POST /career`, JSON, обязательный заголовок `X-Career-Request: 1`.
- Проверка `Origin` (переменная `ALLOWED_ORIGIN`), CORS только для этого адреса.
- Лимит тела запроса 3,5 МБ; фото ≤1,4 МБ, JPEG 200–2000 px, пережимается через `sharp` до 900 px и качества 82 (EXIF и лишние данные удаляются).
- Строгий список полей, запрет лишних полей и honeypot `company`.
- Ограничения текста: ФИО 2–60, Telegram 32, образование/сертификаты 80, «о себе» 20–400; HTML-символы вырезаются, управляющие — заменяются.
- Только известные вакансии/опыт/уровень; телефон строго `+998` и 9 цифр.
- Анти-спам: не больше 4 отправок с одного IP за 30 минут (в памяти, без журналирования данных).
- PDF собирается в памяти: на диск ничего не пишется, после отправки буферы освобождаются.
- Токен бота и chat id HR — только в переменных окружения, браузер их не видит.

## Переменные окружения
| Переменная | Обязательно | Описание |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | токен бота от @BotFather |
| `TELEGRAM_HR_CHAT_ID` | да | chat id HR (HR должен нажать Start у бота) |
| `ALLOWED_ORIGIN` | да | адрес сайта, например `https://1-production-8f16.up.railway.app` |
| `PORT` | нет | порт, по умолчанию `8787` |
| `HR_DRY_RUN` | нет | `1` — проверить приём и PDF без отправки в Telegram (локально) |

## Как подключить бота
1. Создать бота у @BotFather, получить токен.
2. HR открывает бота и нажимает **Start** (бот не может писать первым).
3. Узнать chat id: `https://api.telegram.org/bot<TOKEN>/getUpdates` → `message.chat.id`.
4. Задать `TELEGRAM_BOT_TOKEN` и `TELEGRAM_HR_CHAT_ID` в сервисе.

## Деплой
1. Собрать образ: `docker build -t stanford-hr-api hr-api/` (или отдельный сервис Railway с root directory `hr-api`).
2. Открыть наружу порт `8787` и healthcheck `/healthz`.
3. Спрятать за сайтом: Caddy должен проксировать `/career` на сервис. Пример (правка `Caddyfile` — **только с разрешения владельца**):
   ```
   handle /career {
       reverse_proxy hr-api:8787
   }
   ```
   И в CSP добавить `connect-src 'self'` вместо `connect-src 'none'`.
4. В `career.html` адрес API задаётся в `<meta name="career-endpoint" content="/career">` — по умолчанию same-origin. Если сервис на другом домене, указать полный URL и добавить его в CSP `connect-src` и `ALLOWED_ORIGIN` на сервисе.

## Локальный запуск
```sh
cd hr-api
pnpm install
HR_DRY_RUN=1 ALLOWED_ORIGIN=http://127.0.0.1:8080 PORT=8787 node server.mjs
node --test
```
`HR_DRY_RUN=1` проверяет валидацию и сборку PDF, но не отправляет в Telegram.

## Проверки
```sh
node --test
```
Тесты проверяют валидацию, пережатие фото и генерацию PDF.
