# Бэкап и восстановление

Публичный сайт целиком хранится в этом репозитории GitHub. Только на сервере админки лежат:
**база** (черновики, переводы, учётные записи, 2FA) и **загруженные фото и видео**. Их каждую ночь
забирает GitHub и бот присылает в закрытый чат Telegram. Файлы зашифрованы паролем.

## Что присылает бот
- Каждую ночь в 03:00 (Нукус): файл базы `stanford-db-ДАТА.json.gz.enc` и сообщение
  «✅ Бэкап ДД.ММ.ГГГГ: база …, медиа без изменений».
- Когда фото или видео менялись, а также каждый понедельник: архив `stanford-media-ДАТА.tar.enc.partNN`
  частями до 45 МБ (лимит Telegram для ботов — 50 МБ).
- По понедельникам: «🔍 Проверка восстановления прошла: курсов …, преподавателей …» — GitHub разворачивает
  копию в пустую базу, проверяет наличие всех фото и видео из базы и считает записи.
- Если что-то сломалось: «❌ Бэкап не получился» со ссылкой на подробности.

Секреты (токены, ключ Django, пароли) бот **не присылает**. Храните их в менеджере паролей.

Заменённые и удалённые из админки обработанные фото и видео сохраняются ещё 24 часа после изменения.
Это позволяет бэкапу забрать файл, даже если карточку изменили между выгрузкой базы и архива.
Публикация затем удаляет старые непривязанные файлы; исходные несжатые загрузки не сохраняются.

## Настройка (один раз)
1. **Бот:** в Telegram у @BotFather создайте нового бота (`/newbot`), сохраните токен.
2. **Чат:** создайте закрытую группу, добавьте туда бота, напишите в группе любое сообщение. Откройте
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id":-100…}` — это chat id.
3. **Пароль шифрования:** придумайте длинный пароль и сохраните его в менеджере паролей.
   Без него бэкап не открыть.
4. **Токен выгрузки:** длинная случайная строка (не меньше 32 символов). Например, в Git Bash:
   `openssl rand -hex 32`.
5. **Railway → сервис админки → Variables:** добавьте `BACKUP_TOKEN` = токен выгрузки.
6. **GitHub → репозиторий → Settings → Secrets and variables → Actions → New repository secret:**

   | Имя | Значение |
   |---|---|
   | `BACKUP_BOT_TOKEN` | токен бота |
   | `BACKUP_CHAT_ID` | chat id группы |
   | `BACKUP_PASSWORD` | пароль шифрования |
   | `BACKUP_URL` | адрес админки без пути, например `https://admin.stanford-lc.uz` |
   | `BACKUP_TOKEN` | тот же токен выгрузки, что в Railway |

7. **Проверка:** GitHub → Actions → «Backup to Telegram» → **Run workflow**. Через несколько минут в чате
   появятся файлы и сообщение с проверкой восстановления.

Уведомления «сайт не отвечает» (`uptime.yml`) можно отправлять этим же ботом: в секреты
`TELEGRAM_ALERT_BOT_TOKEN` и `TELEGRAM_ALERT_CHAT_ID` впишите те же токен и chat id.

GitHub отключает ночные задачи, если в репозитории 60 дней не было изменений. Тогда включите их в Actions заново.

## Если всё пропало: переезд на новый сервер
1. **Публичный сайт.** Разверните репозиторий на новом хостинге (Railway или любой сервер с Docker):
   образ собирается из `Dockerfile` в корне. Сайт открывается сразу, админка для него не нужна.
2. **Скачайте из чата** последний файл базы и все части последнего архива медиа.
3. **Расшифруйте** (Git Bash на Windows, терминал на Mac/Linux), подставив свой пароль:
   ```bash
   export PASSWORD='ваш пароль шифрования'
   openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 -pass env:PASSWORD -in stanford-db-ДАТА.json.gz.enc -out database.json.gz
   cat stanford-media-ДАТА.tar.enc.part* > media.tar.enc
   openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 -pass env:PASSWORD -in media.tar.enc -out media.tar
   ```
4. **Админка.** Разверните сервис из папки `cms/` с новой базой Postgres и диском для `MEDIA_ROOT`, задайте
   переменные окружения из менеджера паролей (как в `cms/README.md`). Затем в консоли сервиса:
   ```bash
   python manage.py migrate --noinput
   python manage.py restore_backup --db database.json.gz --media media.tar --yes
   ```
   Команда заменяет данные новой базы данными из бэкапа: пользователи, 2FA, черновики и фото возвращаются.
   Если архив не содержит фото или видео, на которое ссылается база, команда завершится ошибкой.
5. **HR-сервис** разверните из папки `hr-api/` и задайте его переменные (токен бота, chat id HR, `ALLOWED_ORIGIN`).
6. **Домен:** переключите DNS `stanford-lc.uz` на новый сервер, обновите `ALLOWED_ORIGIN`,
   `DJANGO_ALLOWED_HOSTS` и `DJANGO_CSRF_TRUSTED_ORIGINS`, если адрес админки изменился.

## Вручную
Сохранить бэкап без бота (например, перед большими изменениями):
```bash
python manage.py export_backup backup-folder
```
Получатся `database.json.gz` и `media.tar` — те же файлы, что присылает бот, только без шифрования.
Храните их в надёжном месте: в базе личные данные и учётные записи.
