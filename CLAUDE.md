# Stanford Language Center — правила проекта

Лендинг языкового центра в Нукусе. Отвечать владельцу по-русски, коротко и простыми словами.

## Устройство
- Публичный сайт — статика без фреймворков: `index.html`, `style.css`, `script.js`, `theme-init.js`, `content.js`, `assets/`. Раздает Caddy в Docker на Railway.
- `content.js` — данные (курсы, цены, контакты, преподаватели). `node build.mjs` вставляет из них готовый HTML между `<!-- NAME_START -->…<!-- NAME_END -->` в `index.html` и карточки результатов в `results.html`. Генерируемые блоки руками не править — менять `content.js` или `build.mjs` и пересобирать.
- `results.html` + `results.js` — отдельная страница результатов (растёт вместе с данными админки); тема и мобильная карусель в `results.js`.
- `career.html` + `career.js` — анкета для HR: строгая валидация, фото сжимается в браузере и отправляется в сервис [`hr-api/`](hr-api/README.md), который собирает PDF-резюме и отправляет его в Telegram HR через бота. Токен бота и chat id — только в env сервиса; для работы нужны прокси `/career` и `connect-src 'self'` в CSP (правка `Caddyfile` — только с разрешения владельца).
- `site.demoMode` — демо-режим (noindex, тестовые результаты без согласия); `site.demoLabels: false` убирает плашки «Пример» и баннер, оставляя демо-режим служебно включённым.
- Языки: RU / UZ / QQ (каракалпакский, ISO `kaa`), словари `assets/i18n/uz.js` и `kaa.js`. `script.js` на главной и `assets/i18n/language.js` на остальных страницах переводят из русского оригинала и сохраняют выбор. Строка без перевода остаётся на русском. Переводы редактируются в CMS, проверяются `tests/i18n.test.mjs`.
- Тексты каркаса `index.html` редактируются в админке: элемент с `data-text="ключ"` получает текст из `content.js` → `texts`; простые вопросы FAQ — из `faq` (блок `FAQ`). Менять текст — в `content.js`/админке, не в HTML.
- `cms/` — закрытая админка (Django admin, Postgres, 2FA, axes). Локально: `cms/start-admin.bat` или `DJANGO_LOCAL=1`. Публикация собирает все 3 страницы и фото в staging. Локально заменяет файлы с откатом; на сервере при `SITE_PUBLISH_TARGET=github` пишет один коммит через API в явно заданную ветку. Токен владелец задаёт в env; агент сам не коммитит и не пушит без просьбы. Настройка и порядок работы — `cms/README.md`.
- Фото преподавателей, филиалов и занятий сжимаются до сохранения: JPEG без метаданных, до 1600 px и 250 КиБ (`cms/content/media.py`). Исходник до 5 МиБ/16 МП. Старые непривязанные файлы удаляются после коммита; публикация собирает остатки старше 24 часов. Draft media закрыты 2FA; публичные копии — в `assets/uploads/`. Сохраняются фото текущей и предыдущей публикации для отката. Тексты четырёх страниц и атрибуты `data-text-*` редактируются через PageText; после обновления разметки — `sync_page_texts`, новые переводы — `sync_translations`.
- «Практика вне уроков и фото» — модель Practice, данные `practices`, блок `PRACTICES`. Обложка и alt редактируются в CMS. Без фотографии остаётся иллюстрация; выдумывать реальные фото нельзя. Демо-люди удалены из рабочей основы; примеры остаются только в тестовых fixture.
- Caddy проксирует `/career` по `HR_API_UPSTREAM`; CSP разрешает same-origin запросы. HR требует корректный `ALLOWED_ORIGIN` и токен/chat id (либо локальный dry-run). `HR_TRUST_PROXY_HOPS` задаётся явно только за доверенным прокси.
- Новая страница — из `templates/page.html` (порядок в `templates/README.md`). Эффекты (смена слов, счётчики, наклон карточек, лента при прокрутке, бейдж) — `assets/ui.js`, включаются атрибутами `data-loop`, `data-roll`, `data-tilt`, `data-scroll-band`, `data-swing`; блоки страницы результатов (`LOOP`, `SUMMARY`, `BADGE`, `BAND`) собираются из `results`.
- После правки CSS/JS увеличить `?v=` у файла на страницах, где он подключен; версии `content.js` и `uz.js` сборщик выставляет по хешу автоматически.

## Проверки (перед коммитом)
- Сайт: `npm run check` (или по отдельности: `node build.mjs --check`, `node --test`, `python tests/validate_html.py`). Портативный npm может быть сломан — тогда запускать команды напрямую через `node`.
- Эталон текста страницы `tests/page_baseline.json` защищает статический текст и ссылки. После намеренных изменений текста/ссылок: `python tests/update_baseline.py` (показывает разницу), затем `python tests/update_baseline.py --write`. Обновлять только когда разница совпадает с задуманным.
- Админка: `cd cms && DJANGO_LOCAL=1 python manage.py test content`.
- Визуально: 375 и 1280 px, светлая и темная тема, без горизонтальной прокрутки, консоль без ошибок.

## Нельзя без явного разрешения владельца
- Коммитить и пушить (только по просьбе).
- Менять `Dockerfile`, `Caddyfile`, `railway.json`, настройки Railway, DNS, учетные данные.
- Переписывать тексты, цены, контакты и программы курсов; выдумывать реальные данные (демо-блоки помечены «Пример»).
- Секреты не выводить в чат и не коммитить; `.local-credentials` и `.local-2fa/` — только локально. Токены владелец вписывает сам в Railway.

## Дизайн
- Палитра: фирменный желтый `#FFB703` + нейтральные черный/белый/серый; цвета — только CSS-переменные; на желтом текст темный; контраст AA.
- Шрифт Inter (локальный WOFF2), mobile-first, контейнер до 1200 px, отступы кратны 8 px, иконки — inline SVG.
- CSP: `script-src 'self'`, `style-src 'self'` — никаких CDN и инлайн-стилей; библиотеки класть локально в `assets/`. Новые файлы вне `assets/` нужно добавить и в `Dockerfile`, и в `.dockerignore` (там default-deny).
- Анимации — только как украшение: контент виден без JS, уважать `prefers-reduced-motion` и `prefers-reduced-transparency`.
- Ветка `experiment/gsap` — эффекты на GSAP для показа владельцу; в main не вливать без его решения.
- Ветка `experiment/glass` — стеклянный редизайн (матовые панели, плавающая шапка, мобильная нижняя панель); тоже эксперимент, в main не вливать без решения владельца.

## Известные подводные камни
- Windows: в Bash heredoc съедает `\1` и `\\` — Python-скрипты писать файлом; правки по подстроке брать с уникальным контекстом.
- `validate_html.py` требует ровно один `:root {` в CSS.
- Фоновая панель браузера не рисует кадры: CSS-переходы, IntersectionObserver и GSAP двигаются только после скриншота — замерять после него.
- При изменении цен проверять карточку курса и окно курса (dialog), включая курс без семейной цены.
- Меню проверять с клавиатуры: открытие, Tab по ссылкам, уход в контент, Escape, возврат фокуса.
- При изменении `scroll-padding` проверять все переходы по якорям и `scrollIntoView`.
