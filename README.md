# Stanford Language Center

Лендинг языкового центра в Нукусе: статический HTML, CSS и Vanilla JS. Раздает Caddy в Docker на Railway. Светлая и темная темы, фирменный желтый `#FFB703`. Правила работы над проектом — в [`CLAUDE.md`](CLAUDE.md).

## Как поменять курсы, цены и контакты
1. Открыть админку: локально — `cms/start-admin.bat`; на сервере — настроенный секретный адрес.
2. Изменить или добавить запись, загрузить фото, нажать «Сохранить».
3. На главной админки нажать «Опубликовать на сайт». Локально обновятся файлы, на сервере — выбранная ветка GitHub с последующим автодеплоем Railway.

Подробная инструкция владельцу и настройка публикации — в [`cms/README.md`](cms/README.md).
Для правки файлов разработчиком остаётся `content.js` → `node build.mjs` → `npm run check`.
Сборщик обновляет все три страницы; сгенерированные блоки руками не править.

После правки CSS или клиентского JS увеличьте `?v=` на страницах, где подключен этот файл. Версии данных и словаря сборщик обновляет автоматически.

Версии `content.js` и узбекского словаря при публикации обновляются автоматически по содержимому.

### Контакты и карты
- `contacts.phones` — международные номера; `contacts.telegrams` — ссылки `https://t.me/…`. `hrTelegram` и `instagram` отделены от записи.
- `locations` — филиалы: `id`, `name`, `address`, `maps` (Google/Яндекс), необязательные `coordinates: [долгота, широта]` и `googleEmbed` (только код из Google Maps → Share → Embed a map, параметр `pb` не править).
- Контакты публикуются только при `contacts.verified: true` — после подтверждения владельцем.

## SEO
`site.url` сейчас — технический адрес Railway; по нему строятся canonical, og:url и og:image. Когда будет свой домен — заменить `site.url` и пересобрать. Адреса и LocalBusiness не выдумывать.

## Локальный запуск
```sh
node build.mjs
python -m http.server 8080
```
Открыть http://localhost:8080. Нужны Node.js 22+ и Python 3.11+, npm-зависимостей у статического сайта нет. Заголовки безопасности Caddy (CSP) и прокси HR локальный сервер не воспроизводит.

## Проверки
```sh
npm run check
```
Синтаксис JS, актуальность сгенерированного HTML, тесты Node и проверка HTML/палитры. Эталон текста страницы — `tests/page_baseline.json`; после намеренных изменений текста или ссылок: `python tests/update_baseline.py`, затем `--write`. CI на GitHub дополнительно собирает Docker-образ и тестирует админку на Postgres.

## Деплой
```sh
docker build -t stanford-landing .
docker run -p 8080:8080 stanford-landing
```
Healthcheck: `/healthz`, порт по умолчанию 8080 (переменная `PORT`). Railway использует `railway.json`. CSP разрешает только собственные скрипты, стили и шрифты, а в iframe — только карты Google и Яндекса.

Для анкеты задать `HR_API_UPSTREAM` в сервисе сайта — приватный адрес HR API с портом.
Для управления сайтом развернуть отдельную CMS с Postgres и постоянным томом для фото;
настроить `SITE_PUBLISH_TARGET=github`, репозиторий, ветку и токен по инструкции CMS.
Токены владелец задаёт в Railway. Кнопка подтверждает запись в GitHub; успешный деплой проверяется отдельно.

## Структура
- `index.html` — страница со сгенерированными блоками; `results.html` — отдельная страница результатов; `content.js` — данные; `build.mjs` — генерация и проверка данных.
- `script.js`, `results.js`, `theme-init.js`, `style.css` — поведение, тема для страницы результатов, ранняя настройка темы, стили.
- `assets/` — логотип, иконки, иллюстрации практики, шрифт Inter (лицензия `assets/fonts/OFL.txt`), словарь узбекского `assets/i18n/uz.js`, брендированная 404 `assets/errors/404.html`.
- `tests/` — тесты, эталон текста страницы, проверка словаря и HTML.
- `cms/` — закрытая админка (Django).

## Страница результатов
`results.html` собирается вместе с `index.html` одной командой `node build.mjs`: карточки берутся из `results` в `content.js`, поэтому по мере поступления результатов страница просто обновляется. На мобильном карточки листаются каруселью.

## Анкета для работы
`career.html` (+`career.js`) — анкета для HR: контакты, вакансия, опыт, фото и пара слов о себе. Страница проверяет поля, сжимает фото в браузере и отправляет данные в сервис [`hr-api/`](hr-api/README.md); сервис валидирует всё повторно, пережимает фото через `sharp`, собирает **один PDF-файл с резюме** и отправляет его в Telegram HR через Bot API. Токен бота и chat id хранятся только на сервере.

Для работы нужны: отдельный сервис `hr-api`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_HR_CHAT_ID`, `ALLOWED_ORIGIN` и `HR_API_UPSTREAM` у сайта. Прокси `/career` и `connect-src 'self'` уже добавлены в Caddy. Адрес HR-сервиса и секреты на сервере настраивает владелец.

## Демо-режим
`site.demoMode: true` держит страницу вне индексации и разрешает тестовые результаты без согласия. `site.demoLabels: false` убирает плашки «Пример» и баннер демо-версии — так владелец смотрит сайт без служебных подписей. Когда данные станут реальными, выключите `demoMode`.

## Темы и языки
Тема (светлая/тёмная) ставится в `theme-init.js` до отрисовки и переключается кнопкой в шапке. На всех трёх страницах есть RU/UZ; выбор сохраняется между переходами. Тексты берутся из `assets/i18n/uz.js`; строка без перевода остаётся на русском.

## Проверки
```sh
npm run check
```
Синтаксис JS (включая `assets/i18n/uz.js`), актуальность сгенерированного HTML, тесты Node и проверка HTML/палитры. Эталон текста страницы — `tests/page_baseline.json`; после намеренных изменений текста, ссылок, `script.js` или защищённых файлов сборки: `python tests/update_baseline.py`, затем `python tests/update_baseline.py --write`. Обновлять только когда разница совпадает с задуманным. CI на GitHub дополнительно проверяет Docker-образ и тестирует админку на Postgres.


## Перед запуском рекламы
