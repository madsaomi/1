## ⚡ Главные правила взаимодействия:
1. **Никаких изменений вслепую:** Сначала читай код, архитектуру и известные баги, затем изменяй.
2. **Жесткий принцип Plan-First:** Сначала план, архитектура, затронутые файлы и шаги — только потом код. Запрещено вносить изменения без плана!
3. **Параллельная фиксация задач:** Выполняешь задачу — отмечай прогресс в `agents/tasks/active_task.md` и в файле плана.
4. **Фиксация багов:** Столкнулся с ошибкой или сбоем сборки/тестов — опиши её в `agents/bugs_and_fixes/` по шаблону.
5. **Непрерывность истории:** В конце сессии создай новый отчет в `agents/history/` (старые файлы никогда не затирать!).

## Дизайн-система и ограничения владельца — PLAN-030

Текущий запрос владельца разрешает самостоятельные решения и выполнение зафиксированного плана без дополнительных вопросов. Соблюдать Second Brain; разрешение на самостоятельную работу не отменяет ограничений инструментов.

- Стек: только HTML, CSS, Vanilla JS. Не добавлять фреймворки, Tailwind, сборщики или npm-зависимости проекта. Существующий генератор статического HTML сохраняется. Playwright MCP — внешнее средство проверки, не зависимость сайта.
- PLAN-044 / ADR-001 (одобрено владельцем 2026-11-06): публичный сайт остается статикой без фреймворков; допускается отдельный закрытый сервис `cms/` (Python, Django + Unfold, Postgres), который публикует `content.js`, `index.html` и фото коммитом в git. `content.js` — данные, управляемые админкой: не защищен baseline-хэшем; Dockerfile/Caddyfile/railway.json публичного сайта по-прежнему не менять.
- Не менять Dockerfile, Caddyfile, railway.json, конфигурации Railway и логику форм/тем/фильтров/карт/dialog. Допустимы только минимальные презентационные изменения JS с явным описанием.
- Не переписывать тексты, цены, контакты, программы и смысл страницы. Можно улучшать семантику и визуальную иерархию.
- Палитра интерфейса: #FFB703 и нейтральные черный/белый/серый, производные фирменного желтого для состояний. Естественные цвета встроенной карты не менять: никаких filters, blend или overlay над iframe.
- Все цвета — в CSS-переменных; светлая/темная тема совместима с текущим переключателем и системной темой. Желтый на светлом фоне не использовать для мелкого текста; на желтом фоне текст #111. Проверять AA:4.5 для обычного текста,3 для крупного.
- Один шрифт Inter/Geist/Manrope с font-display:swap. Предпочтителен локальный WOFF2, чтобы не изменять production CSP. Шкала14/16/20/24/32/48/64; заголовки600–700, базовый line-height1.5.
- Mobile-first, Grid/Flex, контейнер до1200px, интервалы кратны8px. Радиусы12–16px, тонкие границы, мягкие тени только по назначению, единые primary/secondary кнопки и поверхности.
- Inline SVG одного контура вместо эмодзи/Unicode иконок. Изображения с alt, object-fit и aspect-ratio; ниже первого экрана lazy, LCP-изображение не задерживать lazy loading.
- Hover/focus150–250ms; scroll reveal только через IntersectionObserver без библиотек, с безопасным fallback и prefers-reduced-motion. Контент доступен безJS и при переходе по якорю/фокусу.
- Семантические элементы, подписи полей, видимый focus-visible, цели нажатия≥44px. Не применять градиентный текст, кричащие градиенты, лишние тени или пестрые шрифты.
- Визуальная приемка:375/768/1440px, обе темы,2–3итерации реальных скриншотов с критикой и исправлениями, затем меню/dialog/карта/theme/console. Невыполненные browser-проверки явно отмечать; не подменять их Node VM и не обходить прежние отказы доступа. При необходимости перезапуска после MCP сообщить владельцу «перезапусти Codex».
